# The SAME API with its flaws switched OFF, via the vulnerable=0 environment variable. This is the known-good tier: anything reported against it is a false positive by definition. It is what makes VAmPI usable for measuring precision, not just recall.
#
# ---------------------------------------------------------------------------
# WHY THIS IS SELF-OWNED, AND WHY THE PROOF IS A FILE RATHER THAN AN OBSERVATION
# ---------------------------------------------------------------------------
#
# Ownership verification normally means observing a nonce we asked someone to
# publish. There is nothing to observe here, and nobody to ask.
#
# This target is a container the operator starts on their own machine, from
# docker-compose.yml in the root of this repository, published to 127.0.0.1
# only. The scanner runs on that same machine. Scanning it reaches nothing but
# the operator's own loopback interface. There is no third party with an
# interest in it and no DNS zone to prove control of.
#
# So the proof is the service definition itself: this authorisation is valid
# wherever this repository is checked out, for the person who ran
# `make targets-up` on that host. It is not a claim about any particular
# machine, and no timestamped observation from somewhere else would make it
# one.
#
